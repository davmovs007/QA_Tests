## 📖 Обзор проекта

Проект представляет собой автоматизированный набор тестов для backend-движка e-commerce платформы, провайдера идентификации пользователей, количественных финансовых расчётов и программ лояльности.

Набор тестов полностью валидирует контракты всех **88 функций** библиотеки, бизнес-правила, обработку исключений и граничные условия в соответствии со спецификацией [DOCUMENTATION.md](DOCUMENTATION.md).

## 🧪 Покрытие тестами

Главный тестовый класс **`student.tests.QAApiTestSuite`** содержит более 120 тест-кейсов, сгруппированных по 10 направлениям:

### 1. Валидация входных данных (`ValidationUtils`)
- Валидация форматов email (параметризованные тесты с `@DataProvider`, поддомены, теги `+`).
- Граничное тестирование максимальной длины email (RFC 254 символа: 254 символа принимается, 255 отбрасывается).
- Комплексная проверка паролей: длина (8–64), верхний/нижний регистр, цифры, спецсимволы, запрет пробелов.
- Телефонные номера по стандарту E.164 (границы 7–15 цифр, разделители, международный префикс `+`).
- Почтовые индексы стран: US (5 и ZIP+4), AM (4 цифры), UK/GB, CA (A1A 1A1), generic-форматы.
- Контрольная сумма банковских счетов IBAN по алгоритму ISO 7064 Mod-97.
- Валидация IPv4 (0.0.0.0 – 255.255.255.255, отклонение ведущих нулей и значений >255).
- Валидация веб-адресов HTTP/HTTPS (порты, пути, параметры, якоря).
- Санитизация потенциально опасных XSS-символов (`<`, `>`, `&`, `"`, `'`) в безопасные HTML-сущности.
- Проверка функции `isPositiveNumber` для чисел, нулей, отрицательных значений и `null`.

### 2. Обработка текста и строк (`StringUtils`)
- Генерация URL slug: удаление диакритики, замена спецсимволов и пробелов на дефисы, сжатие дефисов.
- Капитализация слов (`capitalizeWords`) с приведением остальных символов к нижнему регистру.
- Усечение текста (`truncate`) с суффиксом по границе `maxLength` и валидация `maxLength < suffix.length()`.
- Подсчёт непересекающихся вхождений подстроки (`countOccurrences`) с учётом регистра.
- Проверка палиндромов с игнорированием регистра, пробелов и знаков препинания.
- Маскирование платежных карт (`maskCreditCard`) с сохранением последних 4 цифр.
- Переворот порядка слов в предложении с нормализацией одиночных пробелов.

### 3. Финансовые и математические расчеты (`MathAndFinanceUtils`)
- Расчёт налога (`calculateTax`) для 0%, 100% и стандартных ставок; валидация диапазона ставки `[0.0, 100.0]`.
- Расчёт скидок (`calculateDiscount`) и выброс `IllegalArgumentException` при отрицательных значениях.
- Банковское округление `HALF_UP` (`roundToDecimalPlaces`) до заданного числа знаков.
- Проверка кредитных карт по алгоритму Луна (Luhn Mod-10) с поддержкой пробелов и дефисов.
- Конвертация валют (`convertCurrency`) с валидацией строго положительного курса.
- Расчёт сложных процентов (`calculateCompoundInterest`) по формуле $A = P \cdot (1 + r/n)^{nt}$.
- Аннуитетный платёж по кредиту (`calculateMonthlyInstallment`) для нулевой и положительной ставки.
- Относительное процентное изменение (`calculatePercentageChange`) с защитой от деления на ноль.

### 4. Дата и рабочие дни (`DateTimeUtils`)
- Григорианский високосный год (`isLeapYear`) для 1900, 2000, 2023, 2024, 2100, 2400.
- Расчёт дней между датами в прямом и обратном направлениях (отрицательные интервалы).
- Определение выходных дней (суббота и воскресенье).
- Подсчёт рабочих дней понедельник–пятница (`calculateBusinessDaysBetween`) с учётом `start >= end`.
- Добавление рабочих дней (`addBusinessDays`) с автоматическим пропуском выходных.
- Проверка пересечения временных интервалов (`doIntervalsOverlap`) и краевых точек касания.
- Проверка нахождения даты в диапазоне `isDateInRange` с контролем `min <= max`.

### 5. Идентификация и безопасность пользователей (`UserService`)
- Регистрация с авто-назначением роли `CUSTOMER` при передаче `null`.
- Отклонение невалидных имен пользователей (<3 или >30 символов, спецсимволы) и слабых паролей.
- Запрет дубликатов `username` и `email` без учёта регистра.
- Аутентификация и автоматический сброс счётчика неудачных попыток входа.
- **Блокировка аккаунта** (`AccountLockedException`) ровно после 3 неудачных попыток входа.
- Ручная блокировка (`lockUser`) и разблокировка (`unlockUser`).
- Запрет аутентификации для деактивированных пользователей (`deactivateUser`).
- Смена пароля (`changePassword`) с проверкой старого пароля и запретом повторного использования.
- Проверка матрицы полномочий (`hasPermission`) для ролей `ADMIN`, `MANAGER`, `CUSTOMER`, `GUEST`.
- Получение неизменяемого списка пользователей (`getAllUsers`) с защитой от модификации.

### 6. Каталог товаров (`ProductCatalogService`)
- Добавление товара и валидация полей (непустой ID, наименование, категория, неотрицательная цена).
- Запрет добавления товаров с повторяющимся идентификатором.
- Поиск товара по ID и обработка `ResourceNotFoundException`.
- Обновление цены с валидацией отрицательных значений и округлением до 2 знаков.
- Фильтрация по категории (`getProductsByCategory`) только для активных товаров.
- Регистронезависимый частичный поиск по наименованию (`searchProductsByName`).
- Управление жизненным циклом товара (`activateProduct` / `deactivateProduct`).
- Выборка товаров по диапазону цен с сортировкой по возрастанию цены.
- Массовое применение скидки на категорию (`applyCategoryDiscount`) с подсчётом затронутых позиций.
- Выборка всех активных товаров (`getAllActiveProducts`).

### 7. Склад и управление остатками (`InventoryService`)
- Установка и получение доступного (`available`) и зарезервированного (`reserved`) остатка.
- Проверка наличия (`isInStock`) для запрошенного количества.
- Резервирование товара (`reserveStock`) с перемещением единиц из доступного в резерв.
- Проверка `InsufficientStockException` при попытке резервирования больше остатка.
- Отмена брони (`releaseStock`) с возвратом из резерва в доступный остаток.
- Окончательное списание (`deductStock`) из зарезервированного пула.
- Пополнение склада (`restock`).
- **Многопоточное тестирование конкурентности**: одновременные параллельные запросы 10 потоков на резервирование 5 доступных единиц товара с проверкой атомарности и потокобезопасности.

### 8. Корзина и промо-купоны (`ShoppingCartService`)
- Добавление позиций и инкремент количества при повторном добавлении.
- Контроль граничных значений количества товара (1–99) и запрет суммарного превышения 99 штук.
- Запрет добавления неактивных товаров или `null`.
- Удаление позиций и изменение количества с валидацией `ResourceNotFoundException`.
- Применение купонов со скидкой в процентах (`PERCENTAGE`) и фиксированной суммой (`FIXED_AMOUNT`).
- Ограничение фиксированной скидки величиной subtotal (скидка не может превышать сумму корзины).
- Валидация купонов: истёкший срок действия, исчерпанный лимит использований, сумма ниже `minOrderAmount`.
- Удаление купона и очистка корзины (`clearCart`).
- Расчёт промежуточных итогов (`subtotal`), суммы скидки, налога и общего итога (`calculateTotal`).
- Валидация идентификатора корзины `cartId` во всех методах сервиса.

### 9. Управление заказами и State Machine (`OrderService`)
- Создание заказа в статусе `PENDING` с расчётом скидок, налогов и общей стоимости.
- Оплата заказа (`payOrder`): перевод `PENDING` -> `PAID`, валидация карты по алгоритму Луна, проверка точного совпадения суммы.
- Запрет оплаты не-`PENDING` заказов (`IllegalOrderStateException`).
- Отправка заказа (`shipOrder`): перевод `PAID`/`PROCESSING` -> `SHIPPED` с фиксацией трек-номера.
- Запрет отправки неоплаченных заказов (`IllegalOrderStateException`).
- Доставка заказа (`deliverOrder`): перевод `SHIPPED` -> `DELIVERED`.
- Отмена заказов (`cancelOrder`): разрешена только для `PENDING` и `PAID`; запрещена для `SHIPPED` и `DELIVERED`.
- Возврат средств (`refundOrder`): полный и частичный возврат для оплаченных заказов; запрет возврата неоплаченных заказов или сумм, превышающих стоимость заказа.
- Фильтрация заказов по пользователю (`getOrdersByUser`) и статусу (`getOrdersByStatus`).
- **Последовательная цепочка жизненного цикла через `dependsOnMethods`** (создание -> оплата -> отправка -> доставка).

### 10. Программа лояльности и вознаграждений (`LoyaltyService`)
- Начисление баллов (`addPoints`) на текущий баланс и в пожизненный счётчик (`lifetimePoints`).
- Списание баллов (`redeemPoints`) без уменьшения накопленных пожизненных баллов.
- Запрет списания больше доступного баланса (`ValidationException`).
- Определение уровня лояльности по граничным значениям баллов:
  - `0 – 999`: **BRONZE**
  - `1000 – 4999`: **SILVER**
  - `5000 – 9999`: **GOLD**
  - `10000+`: **PLATINUM**
- Сохранение уровня лояльности пользователя даже после списания баллов.
- Проверка персональных скидок по уровням: BRONZE (0%), SILVER (5%), GOLD (10%), PLATINUM (15%).
- Перевод баллов между клиентами (`transferPoints`) с пересчётом балансов и lifetime получателя.
- Запрет перевода баллов самому себе или при недостаточном балансе.

## 💡 Особенности реализации TestNG

1. **Группировка тестов (`groups`)**:
   - `smoke` — базовые сквозные сценарии проверки функционала.
   - `regression` — детальные регрессионные проверки логики и правил.
   - `negative` — негативные сценарии и валидация ошибок.
   - `validation`, `string`, `finance`, `date`, `security`, `catalog`, `inventory`, `cart`, `order`, `loyalty` — тематическая фильтрация.
2. **Параметризация (`@DataProvider`)**:
   - `validEmailProvider` / `invalidEmailProvider` — форматы email.
   - `leapYearProvider` — граничные високосные года.
   - `loyaltyTierProvider` — граничные пороги баллов для уровней лояльности.
3. **Управление зависимостями (`dependsOnMethods`)**:
   - Демонстрация строгой последовательности перехода состояний заказа (`step1_create` -> `step2_pay` -> `step3_ship` -> `step4_deliver`).
4. **Проверка исключений**:
   - Декларативная проверка через `@Test(expectedExceptions = ...)` для стандартных случаев.
   - Точечная проверка через `Assert.expectThrows(Class, Executable)` для проверки сообщений и цепочек вызовов.
5. **Многопоточность и конкурентность**:
   - Использование `ExecutorService`, `CountDownLatch` и `AtomicInteger` для тестирования потокобезопасного кода.

## 🚀 Запуск тестов

### Запуск всех тестов проекта
```bash
mvn clean test
```

### Запуск тестов по конкретной группе
Запуск только smoke-тестов:
```bash
mvn test -Dgroups="smoke"
```

Запуск только негативных сценариев:
```bash
mvn test -Dgroups="negative"
```

Запуск тестов конкретного сервиса (например, заказов или безопасности):
```bash
mvn test -Dgroups="order"
mvn test -Dgroups="security"
```

### Запуск только главного комплексного сьюта
```bash
mvn test -Dtest=QAApiTestSuite
```

## 📊 Отчёты о тестировании

После выполнения тестов Maven Surefire плагин формирует HTML-отчёты в директории:
- `target/surefire-reports/index.html` — полный интерактивный отчёт TestNG.
- `target/surefire-reports/emailable-report.html` — компактный отчёт с детализацией по группам и времени выполнения.
- `target/surefire-reports/testng-results.xml` — машиночитаемый XML для интеграции с CI/CD.
